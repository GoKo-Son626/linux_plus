# ChatGPT 网页端下一周定向提示词

不需要再生成一个大而全教程。把同一周拆成下面 3 次独立请求更有价值；每次都附上 `week_state.yaml`、上周 `completion_report.md` 和必要日志摘要。

## 1. 官方源码事实审计

```text
请作为 Linux remoteproc/RPMI 源码审计员。输入附件是上周状态、错题与本周候选主题。只使用 Linux 官方固定 commit、Ratified RPMI tag、官方 DT binding、lore/厂商官方 repo。输出 claim ledger：每条含结论、[S]/[P]/[H]、repo+commit/tag、path+symbol/section、官方 URL、可能反例。重点寻找过时 API、错误调用顺序、错误 DTS 属性和把规范能力误写成 Linux 已实现的地方。不要生成教程、日程或未构建的完整驱动。
```

## 2. 学习计划反向审查

```text
请作为嵌入式内核教学设计审查员。基于附件中的真实得分、错题、构建/板端证据和 20h 上限，审查 Codex 的本周候选计划。输出：应保留、应删除、前置知识缺口、认知负荷风险、每项可观察验收、若失败时的降级路径。不得因为某主题“上周看过”就默认掌握；不得新增未由错题/目标支持的主题。控制在 1500 中文字以内。
```

## 3. 对抗性周测与评分规约

```text
请基于附件的本周 source pins 和学习目标生成一套闭卷测验，不复用上周原题措辞。题目必须覆盖：概念边界、源码调用顺序、给定代码/日志诊断、平台相关与通用框架的区分。先输出无答案试卷，再单独输出评分 rubric 与标准答案；总分 100，并标出阻断性错误（即使总分高也不能进入下一阶段）。不要假设任何板端命令已经成功。
```

三份短报告用于交叉验证；重复生成多份长教程不会节省 Codex token，也会增加矛盾审查成本。
